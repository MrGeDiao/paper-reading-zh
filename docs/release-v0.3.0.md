# paper-reading-zh v0.3.0

`v0.3.0` 是一次小范围行为变化（minor），主题是触发边界与输出契约。它修复三个结构性触发问题：frontmatter 双条件门控让正文的澄清流程在 Agent 入口执行不到、最高频的「总结这篇」请求处于触发灰区、Agent 场景「按论文实现 X」被导向写报告而不是写代码。另统一了几处硬约束作用域与口径，并首次为触发行为建立可重复的人工回归清单与实机验证记录。

## 背景

此前 frontmatter 触发描述要求「论文锚点 + 深读意图」同时满足，而正文专门设计了「只有其一时澄清一次」的流程；在按 description 路由的运行时里，用户只丢一个 PDF 不说话（最常见开场），skill 根本不会被加载。规划于 2026-06-10 的 v0.3.0 任务清单（T1-T7）针对这些问题逐项落地；执行时结合 v0.2.0 / v0.2.1 已发布的规则基线做了必要适配。

## 变更

### 触发与澄清

- frontmatter 触发描述覆盖三种入口：锚点 + 意图直接进入；只有锚点则澄清一次（深读 / 工程拆解 / 比较）；只有意图则问是哪一篇。意图列表补入 summary/TL;DR，保留 v0.2.0 加入的 evidence audit，排除列表不变。
- 泛化阅读动词（看看、读读、瞅瞅、帮我看、了解一下）直接视为深读意图；只有纯锚点、零附言才澄清。
- 「只澄清一次」口径明确：按边界缺口计数；材料退化确认与比较维度确认属流程内确认，不计入。

### 输出契约

- 总结 / 解读 / 概览 / TL;DR 收编进触发意图，配轻量档位：只输出前置块，不展开正文章节；证据规则照常，不豁免材料范围说明。
- Agent 专属产物型分流：要求直接写代码时先给压缩复现要点清单，再让位编码流程。
- 硬约束作用域声明：适用于深读与工程拆解；调研比较模式前置块为「比较对象与材料范围 + 一句话结论」。字数改为单边上限「默认不超过 3500 中文字」；关键词口径补英文单位（8 个汉字或 3 个英文单词）。

### 防编造

- 新增总则：训练记忆不是可读材料，材料范围只能声明本轮实际读取或用户实际提供的内容；「只能得到摘要」明确覆盖「认出论文但未实际读取全文」的情况。三入口同步，输出前自检同步强化。

### 回归资产

- `docs/trigger-regression-cases.md`：12 个触发边界人工回归用例（输入、期望行为、依据规则条目），声明为人工清单而非自动化测试。
- `docs/validation-2026-08-15.md`：Codex 平台首轮实机回归结果。

## 决策依据

- 规划 T1 引用的 description 现状与仓库不一致（规划写于 v0.2.0 的 144 字符压缩版之前）。经所有者确认按规划长版整行替换，并在规划文本基础上补回 v0.2.0 已发布的 evidence audit 触发词，避免降级；`scripts/check_rules.py` 的 220 字符压缩断言随该决策改为 1024 字符上限与新入口关键短语断言。
- 规划 T4 给出的澄清选项列表同样早于 v0.2.0，执行时保留现行的「深读 / 工程拆解 / 比较 / 证据审计」四选项，不降级。
- 防编造总则不在原规划清单中，由 C9 用例的真实失败驱动（规划 T7 规定失败用例须修正措辞后重测），属于回归流程内的规则补强。
- 实测平台选 Codex：规划允许「Codex 或 Claude Code」，本机 Claude Code CLI 登录态失效无法非交互执行；Claude Code 侧验证了新 frontmatter 在 skill 列表完整展示。

## Validation

- `python3 scripts/check_rules.py`：8/8 PASS（含更新后的 frontmatter 断言）。
- `python3 -m json.tool evals/scenarios.json`：PASS。
- frontmatter 经真实 YAML 解析器校验：单行、826 字符、无「冒号 + 空格」序列、name 未变。
- 12 个触发用例在 Codex（`codex exec`，`gpt-daybreak-blue-latest`，断网沙箱）实测：11 个通过，覆盖单边锚点澄清、泛化动词直入深读、轻量档位、产物型分流、维度确认、乱码不重构等全部新行为；C9 未通过（详见下节已知限制）。

## 已知限制

- C9「只有摘要 + 精读」在被测模型上未通过：超知名论文（Attention Is All You Need）触发训练记忆冒充已读材料，声称「已读取 arXiv v7 全文」；经两轮规则措辞修正仍复现。合成摘要对照组行为完全正确，证明摘要兜底机制本身工作，失败特定于高知名度论文的记忆压制，定性为模型层限制。
- Codex 在多 skill 环境会因 skills 上下文预算截短 description（本机 8 个 skill 时截至 250 字符以内），单边入口与排除列表在路由层不可见，靠触发后的 SKILL.md 正文兜底；本轮 12 个用例行为均被正文规则正确接管。Claude Code 的 skill 列表完整展示 826 字符描述。
- 本轮仅覆盖 Codex 单平台；Claude Code、Claude Project、ChatGPT Project 的同清单回归仍为仓库所有者待办。四平台完整端到端回归仍未完成，公开文案继续只写 Primary / Compatible。
