# paper-reading-zh v0.1.2

`v0.1.2` 修改数学表达规则，规避 Codex Desktop 等客户端中行内 `$...$` 渲染不稳定导致裸 dollar 符号出现在输出里的问题。

## 背景

v0.1.1 发布后发现，Codex Desktop（以及部分其他 Markdown 客户端）对行内 `$...$` 的渲染时有时无：dollar 符号有时被当作普通文本输出，导致读者看到的不是公式而是 `$\tau$` 这样的裸字符串。行间 `$$...$$` 不受影响。

这不是规则包本身的 bug，渲染由客户端决定，但规则可以选择更稳健的默认写法来降低影响面。

## 变更

1. **行内公式默认写法**：从 `$...$` 改为 `\(...\)`。只有当前平台明确支持 dollar-style 行内数学时才使用 `$...$`，且要求 `$` 两侧有 ASCII 空格或标点边界。
2. **单变量叙述**：中文叙述中出现单个变量时，优先用中文术语或普通符号（`x`、`y`），不要反复输出 `$x$`、`$y$`。
3. **符号示例对齐**：SKILL.md 中核心符号示例从 `$\tau$`、`$\lambda$`、`$\alpha$` 改为 `\(\tau\)`、`\(\lambda\)`、`\(\alpha\)`。
4. **同步范围**：`paper-reading-zh/SKILL.md`、`prompts/claude-project.md`、`prompts/chatgpt-project.md` 三个文件均已更新。

未改动：

- 行间公式仍用 `$$...$$`。
- 证据规则、阅读模式、触发边界、术语规则均无变化。
- 不影响安装方式或目录结构。

## 决策依据

- `\(...\)` 是标准 LaTeX 行内数学定界符，在支持 MathJax 或 KaTeX 的客户端上普遍可用。
- 对于不支持任何 LaTeX 渲染的纯文本环境，`\(x\)` 的可读性不比 `$x$` 差，但不会产生孤立 dollar 符号的歧义。
- 单变量用中文术语或 code span（如 `x`）替代，在所有客户端上都稳定显示。

## 已知限制

- ChatGPT 网页端对 `\(...\)` 的渲染支持取决于 OpenAI 的实现。如果在 ChatGPT Project 中遇到 `\(...\)` 不渲染的情况，可以在 Project instructions 中手动把规则改回 `$...$`。本版本的规则已保留“当前平台明确支持 dollar-style 时可使用 `$...$`”的回退条件。
- 这次变更不能保证所有客户端都正确渲染行内数学，渲染始终由客户端决定。
