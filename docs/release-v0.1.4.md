# paper-reading-zh v0.1.4

`v0.1.4` 是一次文档一致性修补，不引入新的阅读模式或证据规则行为。改动集中在把 v0.1.2 遗留的自检与正文矛盾修好、把公开文档对齐到可核验的事实。

## 背景

v0.1.3 发布后的一次评审发现一批文档级问题：v0.1.2 数学规则改版时「输出前自检」清单与反例文本没跟着同步、issue 模板版本示例写死、DESIGN.md 引用公开读者拿不到的内部工具、深读触发词在三入口之间不一致。这些都不改变规则行为（或只是把规则对齐到 v0.1.2 已发布的意图），按轻量语义版本走 patch。

## 变更

1. **修复自检与正文矛盾**：`paper-reading-zh/SKILL.md` 与两份 Web prompt 的「输出前自检」原 `公式是否全部使用 LaTeX` 改为 `公式与多符号表达式是否使用 LaTeX；叙述段的单个变量是否未被强行包成行内公式`。旧写法会让严格执行自检的模型在最后一步把叙述里的裸变量重新包成行内公式，正好回退 v0.1.2 想修的问题。
2. **数学规则反例文本对齐**：反例从 `$x$`、`$y$` 更新为 `\(x\)` 或 `$x$`，与 v0.1.2 的行内公式新默认写法一致（三入口同步）。
3. **触发词同步**：`可行性判断` 补进两份 Web prompt 的深读意图列表，与 SKILL.md 及各自工程拆解模式的措辞对齐，消除文件内前后不一致。
4. **issue 模板版本无关化**：`.github/ISSUE_TEMPLATE/bug_report.yml` 的版本示例改为版本无关写法，不再随发版过时。
5. **DESIGN.md 去除无出处内部工具名**：`quick_validate.py` 改为「AgentSkills 风格的 frontmatter / 目录结构校验（本仓库不附带校验脚本）」；裸 `shuorenhua` 改为「中文文风复查工具（如开源的 shuorenhua 规则包）」，并移除 v0.1.3 引入的 Maintenance Provenance 段，回核三条清单原样保留。
6. **README 版本标识**：badge 更新到 `v0.1.4`，去掉“版本与文档”里随发版过时的单行版本说明。围绕证据演示的 README 正文已随 v0.1.3 发布，本版本不再改动。

未改动：

- 阅读模式、证据规则、触发意图集合、术语规则均无行为变化。
- 行间公式仍用 `$$...$$`。
- 安装方式与目录结构不变。
- 已发布的 `v0.1.3` 版本记录和 `docs/release-v0.1.3.md` 保留原样。

## 决策依据

- 自检项与正文相互矛盾是比“规则不够全”更隐蔽的问题：它让规则包内部自我抵消。这一条对齐属于修复 v0.1.2 未完成的意图，不是新增行为，故归 patch。
- 内部工具名对公开读者不可复现，与项目“可核验”的口径自相矛盾；用可核验表述替换，不承诺仓库不存在的脚本。
- 版本示例写死会在每次发版后过时，改成指向 README badge / CHANGELOG 的版本无关写法后无需再动。

## 已知限制

- 本版本的规则文本改动（自检项修复、反例文本对齐、触发词同步）均为对齐 v0.1.2 已发布行为的修补，不引入新的阅读或证据行为，按验收通则豁免新增真实论文验证记录；四平台完整端到端回归仍未覆盖，排期在后续 minor 版本。
- ChatGPT 网页端对 `\(...\)` 的渲染支持仍取决于 OpenAI 的实现，回退条件（平台明确支持 dollar-style 时可用 `$...$`）自 v0.1.2 起保留。
