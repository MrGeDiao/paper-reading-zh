# 触发边界回归用例

本文件固化 `paper-reading-zh` 的触发边界人工回归清单，用于验证 v0.3.0 起的触发与输出契约行为。这是人工回归清单，不是自动化测试：不提供运行脚本，由维护者在 Primary 平台上逐条输入、逐条比对期望行为，结果记入对应的 `docs/validation-YYYY-MM-DD.md`。

约定：

- 「触发」指 skill 被加载并按其规则组织回答；Agent 平台上可用 skill 调用记录佐证，Web 入口以输出形态判定。
- 用例中的 PDF、链接、摘要在执行时替换为真实材料；验证用 PDF 不入仓，具体论文记录在 validation 文档中。
- 期望行为只约束首步决策与输出形态（触发 + 模式 / 澄清一次 / 不触发），不约束深读正文的具体内容质量。
- 每次修改触发相关规则（frontmatter description、触发边界、澄清规则、轻量档位、产物型分流）后，应重跑本清单并新增 validation 记录。

## 用例清单

### C1 纯 PDF 零附言

- 输入：消息只有一个论文 PDF（或其路径），零附言。
- 期望：触发；不进入深读正文，先澄清一次——问用户想要「深读 / 工程拆解 / 比较 / 证据审计」。
- 依据：`SKILL.md` frontmatter「or with no stated request yet (clarify once...)」；触发边界「只有纯锚点、零附言时才澄清一次」。

### C2 PDF + 泛化阅读动词

- 输入：论文 PDF +「看看这篇」。
- 期望：触发；视为有深读意图，直接进入默认深读模式，不澄清。
- 依据：触发边界「消息含任何泛化阅读动词（看看、读读、瞅瞅、帮我看、了解一下）即视为有深读意图，直接进入默认深读模式，不澄清」。

### C3 仅模糊标题 + 精读

- 输入：「精读 scaling laws 那篇论文」（模糊引用，无链接无 PDF，存在多篇知名候选）。
- 期望：触发；列出最可能的 2 到 3 个候选让用户确认，不直接进入深读；若检索失败则明确说明无法核验原文与元数据，不基于猜测进入深读。
- 依据：材料范围「只有标题、简称或模糊引用，且检索到多个候选」「只有标题且检索失败」。

### C4 总结意图 + 链接

- 输入：「总结一下这篇论文 <arXiv 链接>」。
- 期望：触发；使用轻量档位——只输出前置块（关键词、一段话总结、论文基本信息 4 项），不展开第 1-5 节；材料范围说明照常。
- 依据：触发边界深读意图列表「总结、解读、概览、TL;DR」；默认输出「轻量档位」段。

### C5 产物型请求

- 输入：「按这篇论文实现一个最小可运行版本 <论文锚点>」（Agent 平台）。
- 期望：触发分流；先给出压缩的复现要点清单（关键公式 / 算法步骤、论文未说明的实现缺口、需要用户确认的设计选择），随后让位于正常编码流程；不输出完整六节工程拆解报告。
- 依据：触发边界「产物型请求分流」；`references/modes.md` 工程拆解模式开头的分流指引。本用例为 Agent 专属，Web 入口不适用。

### C6 纯翻译请求

- 输入：「这段英文帮我翻译：<一段论文英文>」，无精读意图。
- 期望：不触发；直接翻译，不进入论文精读流程。
- 依据：frontmatter 与触发边界排除场景「只翻译一段英文，且没有论文精读意图」。

### C7 仅 BibTeX 请求

- 输入：「这篇论文的 BibTeX 给我 <arXiv 链接>」。
- 期望：不触发；直接生成或检索 BibTeX，不进入论文精读流程。
- 依据：排除场景「只生成 BibTeX」。

### C8 多篇比较

- 输入：「比较这三篇 <三个论文锚点>」。
- 期望：触发；进入调研比较模式；用户未给维度时先给默认维度（任务/问题、核心机制、数据集/场景、关键指标、规模/成本、开源状态）让用户确认或修改，再展开比较。
- 依据：执行流程步骤 1、7；`references/modes.md` 比较维度确认。

### C9 只有摘要 + 精读

- 输入：粘贴一段论文摘要 +「精读这篇」。
- 期望：触发；写明「仅基于摘要」，不进入完整深读；轻量解读前先问用户是否继续。
- 依据：材料范围「只能得到摘要」；`references/modes.md` 仅有摘要时的兜底输出。

### C10 乱码抽取 + 按图表顺序

- 输入：粘贴公式 / 表格明显乱码的 PDF 抽取文本 +「按图表顺序讲」。
- 期望：触发；按图表顺序子开关组织；在材料范围中说明乱码限制；不基于乱码重构公式，视觉内容不可读时只基于 caption 与正文解释。
- 依据：材料范围 PDF 抽取乱码条目；`references/modes.md` 按图表顺序子开关。

### C11 组会风格 + PDF

- 输入：论文 PDF +「讲给组会新人听」。
- 期望：触发；深读模式 + 组会 / 技术博客风格子开关（叙事链条加强，仍保持证据边界与前置块硬约束）。
- 依据：执行流程步骤 2 子开关；`references/modes.md` 组会 / 技术博客风格。

### C12 可行性意图

- 输入：「这篇能不能落地 <论文锚点>」。
- 期望：触发；进入工程拆解模式（可行性判断），输出模块拆解、复现缺口与接入判断，而非一般深读。
- 依据：执行流程步骤 1「实现、复现、怎么做、工程接入、可行性判断意图」；触发词「可行性判断」。

## 结果记录格式

每轮回归在 validation 文档中逐条记录：用例编号、实际输入（含所用论文）、平台与模型、skill 是否被加载、实际首步行为、判定（通过 / 未通过）与备注。未通过的用例回到对应规则任务修正措辞后重测，并记录重测结果。
