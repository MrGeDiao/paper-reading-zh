# 触发边界回归用例

本文件固化 `paper-reading-zh` 的触发边界人工回归清单，用于验证 v0.3.0 起的触发与输出契约行为。这是人工回归清单，不是自动化测试：不提供运行脚本，由维护者在 Primary 平台上逐条输入、逐条比对期望行为，结果记入对应的 `docs/validation-YYYY-MM-DD.md`。

约定：

- Agent 平台分别记录“skill 是否被加载”和“是否进入精读流程”，用调用记录与输出佐证；被加载不等于进入精读。排除用例不应主动加载 skill；若加载后退出，记为路由未通过、输出行为通过，不合并记为完整通过。Web 入口只判定输出行为，加载项记为不适用。
- 用例中的 PDF、链接、摘要在执行时替换为真实材料或指定的合成 fixture，并记录来源；验证用 PDF 不入仓，具体论文记录在 validation 文档中。合成材料不作为真实论文结果。
- 期望行为约束首步决策、输出形态、模式组合和多轮材料边界，不代表深读正文整体质量已得到验证。多轮用例须记录每轮实际可见的材料，不能只记录最终答案。
- 每次修改触发相关规则（frontmatter description、触发边界、澄清规则、轻量档位、产物型分流）后，应重跑本清单并新增 validation 记录。

## 用例清单

### C1 纯 PDF 零附言

- 输入：消息只有一个论文 PDF（或其路径），零附言。
- 期望：触发；不进入深读正文，先澄清一次——问用户想要「深读 / 工程拆解 / 比较 / 证据审计」。
- 依据：`SKILL.md` frontmatter「只有论文锚点且无附言时澄清阅读目标」；触发边界「只有纯锚点、零附言时才澄清一次」。

### C2 PDF + 泛化阅读动词

- 输入：论文 PDF +「看看这篇」。
- 期望：触发；视为有深读意图，直接进入默认深读模式，不澄清。
- 依据：触发边界“已有论文锚点或可继承的论文上下文”时，泛化阅读动词补齐阅读意图；没有更具体要求时默认深读。

### C3 仅模糊标题 + 精读

- 输入：「精读 scaling laws 那篇论文」（模糊引用，无链接无 PDF，存在多篇知名候选）。
- 期望：触发；列出最可能的 2 到 3 个候选让用户确认，不直接进入深读；若检索失败则明确说明无法核验原文与元数据，不基于猜测进入深读。
- 依据：材料范围「只有标题、简称或模糊引用，且检索到多个候选」「只有标题且检索失败」。

### C4 总结意图 + 链接

- 输入：「总结一下这篇论文 <arXiv 链接>」。
- 期望：触发；使用轻量档位——只输出材料范围和前置块（关键词、一段话总结、论文基本信息 4 项），不展开核心问题、方法、实验、批判性讨论或复现/应用提示等主体章节。
- 材料范围判定：按工具实际返回的页码或片段核对。若 PDF 有 15 页、仅返回前 11 页，不得声称已读全文；文件存在、总页数或读取成功本身不构成全文读取证据。
- 依据：触发边界深读意图列表「总结、解读、概览、TL;DR」；默认输出「轻量档位」段。

### C5 产物型请求

- 输入：「按这篇论文实现一个最小可运行版本 <论文锚点>」（Agent 平台）。
- 期望：触发分流；先给出压缩的复现要点清单（关键公式 / 算法步骤、论文未说明的实现缺口、需要用户确认的设计选择），随后让位于正常编码流程；不输出完整六节工程拆解报告。
- 依据：触发边界「产物型请求分流」；`references/modes.md` 工程拆解模式开头的分流指引。本用例为 Agent 专属，Web 入口不适用。

### C6 纯翻译请求

- 输入：「这段英文帮我翻译：<一段论文英文>」，无精读意图。
- 期望：不触发；直接翻译，不进入论文精读流程。
- 依据：frontmatter 与触发边界先排除“仅翻译”的请求。

### C7 仅 BibTeX 请求

- 输入：「这篇论文的 BibTeX 给我 <arXiv 链接>」。
- 期望：不触发；直接生成或检索 BibTeX，不进入论文精读流程。
- 依据：frontmatter 与触发边界先排除“生成 BibTeX”的请求，即使附带论文也不进入精读流程。

### C8 多篇比较

- 输入：「比较这三篇 <三个论文锚点>」。
- 期望：触发；进入调研比较模式；用户未给维度时先给默认维度（任务/问题、核心机制、数据集/场景、关键指标、规模/成本、开源状态）让用户确认或修改，再展开比较。
- 依据：执行流程中的模式选择与比较维度确认；`references/modes.md` 比较维度确认。

### C9 只有摘要 + 精读

- 输入：粘贴一段论文摘要 +「精读这篇」。
- 期望：触发；写明「仅基于摘要」，不进入完整深读；轻量解读前先问用户是否继续。
- 依据：材料范围「只能得到摘要」；`references/modes.md` 仅有摘要时的兜底输出。

### C10 乱码抽取 + 按图表顺序

- 输入：粘贴公式 / 表格明显乱码的 PDF 抽取文本 +「按图表顺序讲」。
- 期望：触发；按图表顺序子开关组织；在材料范围中说明乱码限制；不基于乱码重构公式，视觉内容不可读时只基于 caption 与正文解释。
- 依据：材料范围 PDF 抽取乱码条目；`references/modes.md` 按图表顺序子开关。

### C11 组会风格 + PDF

- 输入：论文 PDF +「讲给组会新人听」。
- 期望：触发；深读模式 + 组会 / 技术博客风格子开关（叙事链条加强，仍保持证据边界与前置块硬约束）。
- 依据：执行流程步骤 2 子开关；`references/modes.md` 组会 / 技术博客风格。

### C12 可行性意图

- 输入：「这篇能不能落地 <论文锚点>」。
- 期望：触发；进入工程拆解模式（可行性判断），输出模块拆解、复现缺口与接入判断，而非一般深读。
- 依据：执行流程步骤 1「实现、复现、怎么做、工程接入、可行性判断意图」；触发词「可行性判断」。

### C13 无锚点的泛化阅读意图

- 输入：新会话中只说「帮我看看论文」，不提供标题、链接、PDF、摘要或可继承的论文上下文。
- 期望：触发；只问“是哪一篇论文”，接受标题、链接或 PDF；不进入深读，不自行挑选论文，不重复询问阅读目标。
- 依据：frontmatter「只有阅读意图时问哪篇」；触发边界对泛化阅读动词的锚点前提。

### C14 比较 + 非标准论文类型

- 材料：提供 `evals/fixtures/evidence-audit.md` 与 `evals/fixtures/benchmark-protocol.md` 两份合成材料，均以 benchmark 为主要贡献。
- 输入：「比较这两篇，重点看任务与评估协议、证据覆盖和真实部署边界。」
- 期望：触发；用户已给维度，直接比较；前置块为“比较对象与材料范围 + 一句话结论”，主体围绕两份 benchmark 的协议与证据展开，不恢复逐篇深读的关键词、一段话总结或单篇基本信息块；缺失的协议字段写明缺口，不比较不可比的分数高低。
- 依据：`SKILL.md` 执行流程中的模式、类型组合规则；`references/paper-types.md` 共用前置块；`references/modes.md` 调研比较模式。

### C15 比较 + 按图表顺序

- 材料：提供 `evals/fixtures/evidence-audit.md` 与 `evals/fixtures/system-measurement.md`；只有正文中的表格结果描述，没有表格图片。前者提到 Table 1、Table 2，后者提到 Table 2、Table 3。
- 输入：「比较两篇结论对真实部署的支持程度，按各篇的表格出现顺序讲。」
- 期望：触发调研比较模式并叠加按图表顺序；保留比较前置块，不增加关键词、一段话总结或单篇基本信息块；每个表号带所属论文，分别保持原文顺序，不合并两个 Table 2；只解释可读正文描述，不猜表格布局或不可见图像。
- 依据：`references/modes.md` 按图表顺序子开关与调研比较模式；`SKILL.md` 模式、类型和子开关的分工。

### C16 benchmark + 工程拆解

- 材料：提供 `evals/fixtures/benchmark-protocol.md`，这是描述任务、输入输出、数据划分、评估协议及接入缺口的合成短文。
- 输入：「对这篇 benchmark 做工程拆解，判断能否接入我们的中文客服工单分类评测；先分析，不写代码。」
- 期望：触发工程拆解，保留“工程接入判断”等主体章节；说明数据适配、推理输出校验和指标计算等模块，区分短文给出的协议与未说明的许可、评估器细节、版本信息；讨论英文三分类向中文业务迁移的验证缺口。不得把深读模式“复现/应用提示”的省略条件套到工程接入判断上，也不因明确工程意图而假设存在官方代码或可用数据集。
- 依据：`SKILL.md` 默认输出中“复现/应用提示”的适用范围；`references/modes.md` 工程拆解模式；`references/paper-types.md` 数据集 / benchmark 论文。

### C17 两轮追问继承仍可核对的原文

- 第一轮：提供 `evals/fixtures/system-measurement.md` 并要求精读；确认原文已被实际读取，其文本与读取记录仍保留在第二轮上下文中。
- 第二轮输入：「继续解释 Table 2 和 Table 3，为什么它们还不能证明是调度器导致了改善？」不新增论文材料。
- 期望：可沿用前轮仍可核对的原文与论文上下文，直接回答；引用表格结果、前后对比设计和工作负载变化时可定位到该短文的 Results、Measurement setup 或 Limitations。不能因本轮未重读就要求重新上传，也不能把沿用材料写成本轮新核验。
- 依据：`SKILL.md` 材料范围中的前轮原文沿用规则与执行流程中的追问继承。

### C18 前轮答案或对话摘要不能代替原文

- 材料条件：新建隔离会话，只粘贴这段回顾：「上一轮回答摘要：EdgeCache 降低了请求延迟，Table 2 支持这个结论。」不提供原文、有效链接或可访问的 fixture；这是前轮答案的回顾，不是论文摘要或原文引文。
- 输入：「继续给出 Table 2 的完整数值，并解释原文是怎样排除工作负载变化影响的。」
- 期望：说明当前只有前轮答案或对话摘要，不能据此核对 Table 2 或实验控制；请求可核对原文，或在确有可访问来源时先重新读取。未取得原文前不补数值、页码、实验控制或“已读全文”声明，也不把前轮答案当作独立证据。
- 判定条件：若运行环境实际仍能读取原文，须记录来源；该跑不能作为“原文不可用”条件下的通过证据。
- 依据：`SKILL.md` 材料范围“上一轮回答或对话摘要不能代替缺失原文”及需要原文时重新读取或说明缺口的要求。

## 结果记录格式

每轮回归在 validation 文档中逐条记录：用例编号、实际输入（含所用论文或 fixture）、平台与模型、各轮实际可见材料、skill 是否被加载、是否进入精读流程、实际首步行为、路由与输出行为各自的判定（通过 / 未通过 / 未验证 / 不适用）及备注。用例清单只记录期望；未执行的用例不能记为通过。未通过的用例核对规则与运行环境，修正后记录重测结果；不能用正文退出掩盖排除场景的路由失败。
